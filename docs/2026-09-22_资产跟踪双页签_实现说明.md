# 资产跟踪双页签实现说明

日期：2026-09-22。范围：将现有黄金看板与境内美股ETF看板合为一个网页的“黄金 / 美股 ETF”页签。本轮不调整指标、计算规则、ETF名单或数据源。

## 页面与输入

`scripts/build_site.py` 继续按原函数生成完整黄金页，再调用 `merge_assets.write_merged_site` 与 `data/etf_tracking.html` 合并。后者是ETF项目经过校验的自包含成品快照，不携带凭据，也不在网页中请求Wind或Tushare。

`site/index.html` 为自包含成品：两页的样式与脚本分别保留，统一顶部页签。首次打开默认黄金；`#gold`、`#us-etf` 可直接进入相应页。切换时保留内部筛选与图表状态，返回页面顶部。支持方向键、Home、End。黄金证据链接在本页展开，不跳转重载整份合并页。

未修改黄金 `build_html` 内部计算及页面内容；黄金原有指标、观测日期、滞后状态和已知局限继续展示。两边数据日期独立，不以统一构建时间代替数据日期。离线文件是当时的快照；只有部署到共享网址并更新后，其他人刷新网址才能取得新版。

## 更新方式

首次导入或只在本地合并已有ETF页面：

```sh
python3 scripts/build_site.py --etf-page '/Users/xu/code/ETF研究/QDII ETF 溢价率/site/美股ETF跟踪.html'
```

之后普通 `python3 scripts/build_site.py` 始终读取保存的ETF快照。因此现有GitHub Actions再次构建，以及黄金周更，都不会丢失ETF页签。CI仍只渲染已提交数据；本轮不改CI配置。

黄金完整周更入口保持 `scripts/update_data_and_commit.py`，仍刷新原Wind/FRED/CFTC数据。ETF项目先完成原有日更后，可用同一发布入口的ETF模式：

```sh
python3 scripts/update_data_and_commit.py --etf-page '/Users/xu/code/ETF研究/QDII ETF 溢价率/site/美股ETF跟踪.html'
```

此模式只导入ETF快照、重建合并页与运行检查，不查询黄金数据。只允许提交 `data/etf_tracking.html`、`site/index.html` 两项；若出现黄金市场CSV等其他tracked变更则停止。该命令默认会commit、push，必须在发布授权后使用；仅构建预览请使用前一个命令。

输入缺失、JSON损坏、未来日期、名单数量/分组或代码唯一性不符时，合并停止，不退回黄金单页。两项输出先准备完整再替换，写入失败恢复旧缓存与旧成品。目录中的未跟踪研究文件不纳入提交。
